# ARCHITECTURE.md — «ЭТАЖ 9»

Живой документ. Обновляется каждую сессию (BRIEF Section 4).

## Обзор

Godot 4.4+, рендер **OpenGL Compatibility** (см. D-006; бриф изначально
фиксировал Forward+), GDScript со статической типизацией. Сигналы вместо
полупериодического опроса; контент — данные (Resource), композиция сцен
вместо наследования. Сложность проекта живёт в «ощущении», не в алгоритмах —
код скучный и отлаживаемый.

## Автолоады (порядок инициализации фиксирован)

| # | Имя | Файл | Ответственность |
|---|-----|------|-----------------|
| 1 | `EventBus` | src/autoload/event_bus.gd | Только сигналы. Вся межсистемная связь. |
| 2 | `SettingsService` | src/autoload/settings_service.gd | user://settings.cfg, дефолты, применение громкостей к шинам. |
| 3 | `GameState` | src/autoload/game_state.gd | Этаж/seed/фаза/стрик. Чистые данные. Мутирует Loop Manager (M1). |
| 4 | `AudioDirector` | src/autoload/audio_director.gd | Пул AudioStreamPlayer3D, `play_varied()`, имена шин. |
| 5 | `Director` | src/autoload/director.gd | Tension 0..100, сидированный RNG (детерминизм). Полная логика — M2. |

Порядок: EventBus первым (все на него подписываются), SettingsService раньше
потребителей настроек, Director последним (зависит от EventBus).

## Поток сигналов (M0-срез)

```
Main._ready() ──► GameState.start_run() ──► EventBus.run_started(seed)
                                                  └─► Director: seed RNG, tension = 0
SettingsService.set_setting() ──► EventBus.setting_changed(key, value)
       ├─► Main: video/internal_height → пересоздать размер SubViewport
       └─► Player: чувствительность / инверсия / FOV
Director.tension (setter) ──► EventBus.tension_changed ──► (M2+: ambience mix, lamps…)
```

## Пайплайн рендера (низкое разрешение)

```
Window (1280×720, resizable)
└── Main (Node, src/main.gd)
    ├── GameViewportContainer (SubViewportContainer, texture_filter = NEAREST,
    │   │                      stretch = false; scale/position задаёт Main)
    │   └── GameViewport (SubViewport 640×360 | 480×270 | 320×180,
    │       │             audio_listener_enable_3d = true  ← ОБЯЗАТЕЛЬНО)
    │       └── World (Node3D): WorldEnvironment, Flight, Player
    └── DebugOverlay (CanvasLayer, только debug-сборки) — рисуется в нативном
        разрешении, НЕ внутри low-res вьюпорта (читаемость).
```

UI (субтитры, меню) живёт вне SubViewport — в нативном разрешении.
Масштабирование: единый float-скейл по меньшей стороне + леттербокс;
целочисленный скейл не форсируем.

## World metrics (канон M1, из flight_module.gd)

- Модуль = **марш (полширины шахты) + этажная площадка**. Один модуль = один
  «этаж» игровой логики.
- Ступень: подъём **0.2 м**, проступь **0.3 м**, **12 ступеней** (B1 = 13 при
  тех же габаритах марша — общая высота/длина не меняются, чейнинг стабилен).
- Марш: подъём **2.4 м**, длина **3.6 м**, ширина **1.05 м** (x∈[-1.1,-0.05]).
- Площадка: глубина **1.5 м**, полная ширина шахты **2.2 м**. Потолок площадки —
  слаб модуля L+2, чистая высота ≈ **2.3 м** (B2 = −15%).
- Глубина модуля **5.1 м**. Чейнинг: `T(L+1) = T(L) * (rotY(π) + (0, 2.4, 5.1))`
  — switchback: марши чередуют стороны, площадки тайлят торцы шахты,
  дверные стены соседних паритетов закрывают противоположные торцы.
- Дверь: 0.9 × 2.05 м; номера квартир: **{2·этаж+17, 2·этаж+18}** (9-й = 35/36,
  как в премисе; «№40» Жильца остаётся за пределами нумерации — намеренно).
- Игрок: капсула r=0.3, h=1.7, глаза на 1.62 м. Перила 0.95 м, прыжка нет.

## Модель сегментов и commit-пайплайн (M1)

- **Вопрос Q(L)** = {пропсы площадки L} + {марш модуля L+1}: всё, что игрок
  видит, стоя на площадке L (включая марш вверх). Аномалия Q либо на площадке
  (A1 обувь, C1 лампа), либо на марше выше (B1 ступени, D1 граффити, E3 следы),
  либо событийная (F2 — триггер входа в марш).
- Подъём по маршу L+1 → прибытие на площадку L+1 → `judge(Q, UP)`.
  Спуск по маршу L → прибытие на площадку L-1 → `judge(Q, DOWN)`.
- Тредмил: окно из 4 модулей (уровни -1..+2). На commit: VHS-глитч (0.14 c)
  → re-anchor (прибывшая площадка становится origin, игрок переносится тем же
  жёстким преобразованием) → рециклинг крайнего модуля → reveal стенсила
  (delayed verdict) → стейдж нового Q (ребилд модуля +1; носители выше игрока
  или меняются точечными хуками). Reset: то же под rewind-перемоткой (~1.1 c),
  игрок заморожен, весь мир ребилдится от этажа 1.
- Прошлые аномалии остаются видимыми позади игрока (память мира, как в Exit 8),
  пока модуль не рециклится.

## Журнал решений

- **D-001 (M0; закрыто в M1).** Ступени CSG — визуальные; коллизия — невидимый
  наклонный `StairRamp` по линии носов ступеней. В M1 рампа ПРИНЯТА как
  постоянная реализация stair-smoothing из Section 8: ноль джиттера капсулы
  по построению, «честный» пошаговый step-up отклонён как лишняя сложность
  (boring > clever). Визуальной разницы от первого лица нет.
- **D-002 (M0, постоянно).** Сырая мышь обрабатывается в корневом viewport
  (`src/main.gd`) и пробрасывается в `Player.apply_look()`. Причина: события,
  проходящие через SubViewportContainer, трансформируются его масштабом —
  чувствительность зависела бы от размера окна.
- **D-003 (M0, постоянно).** «Compiled out» для debug-оверлея в GDScript
  недостижимо буквально; гейтим инстанцирование `OS.is_debug_build()`.
  Release-экспорт оверлей не создаёт. Перед публичной раздачей билда можно
  дополнительно исключить `src/dev/*` фильтром экспорта.
- **D-004 (M0, решение для M4).** В Godot нет per-bus aux-send'ов. Реверб-хвост
  для позиционных SFX делаем дублированием ваншота на шину Reverb вторым
  плеером пула (стандартный обходной путь). Реализация в M4.
- **D-005 (M0; закрыто в M1).** Прямой греябокс M0 заменён switchback-китом
  `flight_module.gd` + `chain_manager.gd` (см. «Модель сегментов»).
- **D-007 (M1).** Рестейдж мира маскируется VHS-глитчем на КАЖДОМ commit'е
  (Section 5 трактует tracking-глитч как системное событие). Глитч одинаков
  для верных и неверных ходов — наличие аномалии не телеграфируется. Бонус:
  CSG-ребилд (~мс) прячется в закрытом кадре. В M3 заглушка станет шейдером.
- **D-008 (M1).** Окна подъезда чередуют стороны шахты из-за поворота модулей
  (реальная панелька так не может). Осознанное упрощение греябокса; решение —
  в M3 при настоящем ките (либо окна только на одном паритете).
- **D-009 (M1).** GUT 9.4.0 (MIT) в addons/gut: 9.5.0 требует Godot 4.5+,
  на 4.4.1 не компилируется.
- **D-006 (M0.1, решение оператора).** Базовый рендер: Forward+ → **OpenGL
  Compatibility**. Факты: на машине гейм-директора (AMD Radeon iGPU, Vulkan
  1.4.315) оба Vulkan-метода Godot (Forward+ и Mobile) рендерят освещаемые
  материалы чёрным (подтверждено PNG-дампами из движка: видны только unshaded
  Label3D); OpenGL-путь работает. Все DoD проходят через эту машину.
  Последствия для M3: волюметрики/SDFGI в Compatibility нет (и не нужны);
  туман делаем depth/vertex-fog в нашем PSX-шейдере — аутентичнее PS1.
  Forward+ остаётся доступен флагами
  `--rendering-method forward_plus --rendering-driver vulkan`.

## Тесты

GUT ставится в M1. Объекты тестирования (BRIEF Section 4): вердикты Loop
Manager, математика Director, выбор аномалий, детерминизм seed. Loop Manager
пишется как чистый класс без ссылок на сцену — тестируется без рантайма.

## Производительность

Бюджет: 60 fps на интегрированной графике при 640×360; ноль аллокаций на кадр
в hot path (пул аудиоплееров уже соблюдает это; `play_varied` не аллоцирует).
Профилировка после каждого майлстоуна. Заявленных цифр пока НЕТ — контейнер
разработки headless, замеры делает оператор (docs/PLAYTEST_M0.md).
